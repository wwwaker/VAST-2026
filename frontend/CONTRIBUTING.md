# 前端代码规范

在 `frontend/` 中运行 `npm ci` 后，提交前执行 `npm run check:code`。它检查格式、ESLint 规则及 TypeScript 类型；涉及交互时，再运行对应工作区的功能与浏览器检查，命令见根目录 `MAINTENANCE.md`。

## 格式与组织

- 使用 UTF-8、LF、两个空格缩进及文件末尾换行。Prettier 统一双引号、分号、尾逗号与 100 列目标宽度；JSX 每个属性单独一行。SVG 路径、URL 和不可拆分字符串允许超过目标宽度。
- 每条语句独立书写；每个变量声明只声明一个绑定，所有条件和循环体使用大括号。函数、类型、状态初始化、派生值、事件处理和渲染按职责分组，以空行分隔。
- 组件使用 PascalCase，函数与变量使用 camelCase，类型表达具体数据含义。图形坐标 `x/y`、比较器 `a/b` 和简短索引可用短名；多阶段业务逻辑使用可辨认的名称。
- 重复的 UI 和基础能力放在 `shared/`，数据集语义留在各自 `features/`。共享层不得导入工作区或应用入口；当前页面不得导入 `compatibility/`。ESLint 检查这些边界。
- 优先拆出有含义的纯函数或组件，降低复杂分支的嵌套；不为换行把简单表达式拆成无意义的中间变量，不为了复用而合并不同数据集的时间或证据语义。

## 注释与 React 状态

- 为时间单位和端点、调查范围、主选／补充证据、缓存失效、快照恢复以及布局算法的限制说明原因。注释放在相关逻辑前，不逐行复述代码；公共契约和复杂算法用简短 JSDoc。
- JSX 的大段区域可用注释说明职责；简单按钮、显而易见的赋值和标准 Hook 不需要注释。
- 遵守 Hook 调用顺序和依赖检查。以查询键、稳定引用或选区身份驱动的效果，若不能按常规依赖展开，必须在局部禁用前解释触发边界及不展开依赖的原因。禁止文件级关闭 Hook 检查。
- 使用明确类型与 `unknown` 缩小范围，避免 `any` 和无依据的非空断言；接口字段名称保留服务端契约，不做表面改名。
- 风格整理保持行为一致；会改变筛选、请求时机、历史恢复、证据解释或图布局的修改，应单独说明并验证。

## 常用命令

```shell
npm run format        # 统一排版
npm run lint:fix      # 修复可自动处理的规则
npm run check:code    # 格式 + 静态规则 + 类型
npm run build        # 类型检查 + 生产构建
```

Prettier 与 ESLint 的开发依赖锁定具体版本，配置随仓库分发；编辑器支持 EditorConfig 时会自动采用基本缩进和换行设置。格式检查排除依赖、构建产物、锁文件及仅本地保留的历史来源文档。
