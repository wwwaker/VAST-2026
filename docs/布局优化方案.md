# 调查工作区布局优化方案

**文档状态：**实施中；第一阶段布局骨架已编码，待浏览器验收
**目标版本：**课程 / VAST Challenge 2026 可演示原型
**编制日期：**2026-11-05

## 1. 目标与范围

把目前以纵向堆叠为主的调查页整理成一个可聚焦、可调整的工作区。分析者应能在主要画布中查看时间线、关系图或基线比较，并按需要展开事件流和证据；常用时间控制和筛选状态始终可见，说明性文字不再占用大块常驻空间。

本方案覆盖 MC1、MC2 和自建数据集共用的页面布局、面板交互、浅色 / 深色主题适配和响应式行为。数据语义、SQLite 查询与后端接口不在此轮改动范围内。实现前保留现有视图能力及其筛选联动，不恢复章节式讲解导航或“讲解顺序”栏。

## 2. 当前页面观察

当前页面由 [App.tsx](../frontend/src/App.tsx) 组织：顶部工具栏和问题栏之后，主体区域放置主画布与证据侧栏；页面底部再依次放置回放条和状态条。

- 顶部工具栏同时放数据集、关键词、主题、减少动效、帮助和渲染基准入口，横向空间紧张时容易拥挤。
- 主画布通过一排标签在事件时间线、关系图和基线比较之间切换。概览页内部又按顺序放置图表、图例、锚点、干预建议和事件流。
- 事件流有独立边框和最高 240px 的高度；证据侧栏固定占用右侧空间，MC1 会进一步加宽。
- 底部回放区自身有两行内容，下面另有状态条，形成连续的常驻横条。
- 多处使用独立边框面板。数据和控件都可用，但页面更像若干模块堆叠，主要调查画布不够突出。

这些观察来自当前组件结构和样式，不代表用户任务或数据流程需要重做。优化重点是重新分配空间、降低常驻信息密度、让次要内容按需出现。

## 3. 布局原则

1. **画布优先：**当前所选调查视图占据主区域；工具和辅助信息贴近相关画布，避免重复标题、描述和边框。
2. **面板可停靠、可收起：**借鉴 VS Code 的工作区组织方式，支持将事件、证据和关系等辅助内容在侧边或底部展开，并通过拖动分隔线调节尺寸。
3. **浮动但不遮挡：**视图切换、画布选项和轻量信息采用贴边浮动工具条；较大的内容面板可暂时浮出，支持固定回侧栏 / 底部。默认布局不允许多个大面板互相覆盖。
4. **高频常驻、低频按需：**时间游标、播放控制、当前筛选摘要和主要视图切换常驻。解释性提示、技术字段和次要动作改为折叠区、悬浮提示或详情页签。
5. **三数据集一致：**布局状态与数据适配解耦。MC1 双声道、MC2 多实体关系和自建 run 标签仍按各自能力显示，不用同一套固定字段强行填满面板。
6. **主题与动效完整：**所有表面、边框、图表和浮层使用现有主题 token；节点与面板过渡尊重减少动效设置。

## 4. 建议的信息架构

### 4.1 桌面工作区

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 全局栏：数据集 / 案例、搜索、主题、更多操作                         │
├──────────────────────────────────────────────────────────────────────┤
│ 调查画布：视图浮动切换器（时间线 | 关系图 | 基线比较）               │
│                                                                      │
│                 当前主视图 / 主要证据                                │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 可停靠调查面板：事件流 / 关系上下文 / 证据 / 笔记（可收起、可调高）   │
├──────────────────────────────────────────────────────────────────────┤
│ 单行调查控制条：回放 / 时间游标 / 时间刷选状态 / 筛选摘要 / 笔记入口 │
└──────────────────────────────────────────────────────────────────────┘
```

右侧证据检查器可作为调查面板的一种停靠位置。默认桌面布局建议保留一个主要检查器；用户可以把它移到底部或收起，避免事件流、关系图和证据同时抢占画布空间。分隔线拖动后应设置合理的最小 / 最大尺寸，刷新后恢复最后一次布局。

### 4.2 主画布与视图切换

- 将“事件时间线 / 关系图 / 基线比较”改成画布边缘的紧凑浮动切换器，作为视图控制，不做章节或讲解步骤指示。
- 保持三种视图互斥地占据主画布，避免多张缩小的图表同时出现、难以阅读。面板化的事件流、证据和关系上下文可与主视图并列或停靠。
- 当前视图在切换器中保持明确选中态；切换时保留数据集、筛选窗口、选中事件与主题状态。
- 时间线继续作为发现入口；选中时间范围或事件后，事件流与证据检查器更新。关系图保留多级关联能力和层级视觉编码。基线比较继续明确展示当前窗口与前一等长窗口。

### 4.3 调查面板

将目前概览页中固定占位的事件流改为可停靠的底部面板。面板标签至少包含“事件”“证据”“笔记”；“关系上下文”可作为证据检查器中的页签，或在关系图视图下作为上下文面板。选中事件时可提示证据面板有新内容，但不应强制打开并挤压画布。

面板标题栏只保留当前标题、结果数量和常用图标动作（收起、固定 / 停靠、关闭）。数据集说明、异常定义和完整字段信息放进可聚焦的提示或折叠详情。关闭与收起需语义区分：关闭隐藏当前面板，收起保留标签入口和布局位置。

### 4.4 单行底部控制条

把目前分开的回放条与状态条合并为一个高度稳定的控制条：

- 左侧：播放 / 暂停、前后步进、当前时间。
- 中部：时间进度 / 刷选滑轨，宽度随窗口伸缩。
- 右侧：回放遮蔽、筛选状态、清空筛选、记录筛选快照等动作。
- 回放遮蔽说明等解释性文字改为信息提示；提示必须可通过键盘焦点访问，不能只依赖鼠标悬浮。
- 窄屏时次要动作折入工具菜单，时间和播放控制仍直接可达；不得压缩到按钮文字重叠。

## 5. 浮动控件、折叠与悬浮信息

### 浮动工具条

视图切换器固定在画布左上或右上安全区，避免覆盖图表主数据。各视图的图层、布局和比较选项放在紧邻的工具按钮中；按钮使用图标并带中文 `title` / 可访问名称，选项较多时使用菜单或分段控件。

### 可调节面板

- 底部事件面板允许垂直调整高度；右侧检查器允许水平调整宽度。
- 拖动分隔线需支持键盘操作或提供等价的尺寸选项，并显示焦点状态。
- 收起状态保留窄标签栏或明确的展开按钮，展开后恢复上次尺寸。
- 第一版只支持约束明确的停靠布局和单个浮出面板；自由拖放到任意坐标、多个重叠浮窗不列为首版要求。

### 悬浮提示与折叠内容

- 适合悬浮提示：更新时间、源时区说明、统计口径、节点完整 ID、关系边证据数、截断提示和纯文本字段解释。
- 适合折叠展开：原始 JSON、长消息、MC1 内部审议全文、关系筛选、基线计算说明及自建标签详情。
- 不能仅在悬浮时出现：事件正文、风险状态、时间游标、选中标记、数据来源与关键证据。触屏和键盘用户都需要能查看这些内容。
- Tooltip 应可聚焦触发、可读、不遮挡当前操作目标，并在窄屏降级为点击打开的小型详情层。

## 6. 视觉与动效方向

保持现有浅色、深色和跟随系统模式。通过背景层级、细边界、局部强调色、透明度和阴影区分画布、停靠面板、浮动工具条与选中项；不要让每个控件都成为一个独立卡片。信息层级依赖文字、图标和结构，不单独依赖颜色。

节点选择或关系中心变化时，旧邻居淡出，新邻居渐显，稳定节点保持位置；面板展开 / 收起采用短距离位移与透明度过渡，避免大幅缩放或持续运动。手动启用“减少动效”或系统减少动态效果时，过渡改为即时状态切换。

## 7. 响应式行为

- **宽屏：**主画布、可调右侧检查器与底部事件面板并存，用户可调整分隔比例。
- **中等宽度：**检查器默认收起为侧边按钮或改为覆盖式抽屉；底部面板保留单一活动页签。
- **窄屏 / 触屏：**画布占满主体；工具条提供点击展开菜单，面板以单层抽屉呈现；不要求拖动浮窗，调整大小用预设尺寸或全屏切换。
- 各断点下验证中文长文本、事件行标签和关系边标签不互相覆盖；重要操作有足够点击区域。

具体断点与面板尺寸在实施阶段按实际浏览器窗口测量，不把现有 1180px 媒体查询直接视为最终设计值。

## 8. 实施顺序

1. **骨架收敛：**调整全局栏、主画布、底部调查面板和合并后的单行控制条；先保留现有数据和组件行为。
2. **面板交互：**实现检查器开关、底部面板页签、收起 / 展开、拖动分隔线和布局状态恢复。
3. **浮动视图工具：**将三视图切换器放入画布工具条，加入各视图必要的轻量选项；验证切换后调查状态保留。
4. **内容密度整理：**把低频说明移入 tooltip / 折叠区，检查事件流、双声道、raw 记录和笔记的空间表现。
5. **视觉与响应式验收：**逐项检查浅色、深色、减少动效、键盘焦点和窄屏抽屉行为，再更新截图与 UI 检查脚本。

每一步都以三种数据集的已有工作流回归，避免布局重构造成某一数据集的专属语义被隐藏。

### 当前实现进度（2026-11-05）

- 已完成：移除章节式导航；视图切换放入画布工具条；事件流从时间线视图中拆出，可选择底部、左侧或右侧停靠，支持收起、拖动 / 键盘调整尺寸，并保存布局偏好。
- 已完成：回放与状态信息合并到同一控制栏；时间游标可通过滑块拖动，遮蔽说明移入可聚焦的信息提示。
- 待验收：桌面与窄屏尺寸下的实际浏览器布局、主题与减少动效、三种停靠方向和后端笔记链路回归。
- 尚未实现：证据检查器可停靠与调整尺寸、完整的单行窄屏操作收纳、事件 / 证据 / 笔记多页签面板。

本阶段的事件流定位是独立调查面板，因此右侧停靠会与证据检查器并列；窄屏采用覆盖式面板，避免压缩主画布到不可读宽度。后续若将证据检查器也纳入可停靠布局，再统一处理两个面板的空间分配和标签入口。

## 9. 验收标准

- 页面底部从回放区加状态区收敛为一条主控制条；解释性说明不再固定占据第二行。
- 主画布能在时间线、关系图、基线比较之间切换，切换后筛选、时间游标和选中事件状态符合预期。
- 事件流、证据和笔记可以按需展开或收起；桌面检查器与事件面板尺寸可调，面板状态刷新后可恢复。
- 选中事件后可在不离开当前分析视图的情况下查看证据；用户可以主动隐藏检查器以恢复画布空间。
- 浅色 / 深色主题下，浮动工具条、面板、边界、悬浮提示和图表均可辨认；减少动效偏好得到尊重。
- 关键字段与关键证据不依赖鼠标悬浮才能发现；键盘可以切换视图、展开主要面板并聚焦提示内容。
- 在 MC1、MC2 和自建数据集中完成同一条“选事件 → 看证据 → 回到时间线或关系图”的流程；专属字段仍可追溯到原始记录。
- 桌面与窄屏下无面板互相遮盖、标签重叠、横向溢出或无法关闭 / 重新打开的状态。

## 10. 暂不纳入首版

- 多个自由浮动窗口同时拖放与跨屏记忆。
- 用户自定义任意面板组合、保存多个命名工作区和云端同步布局。
- 自动根据异常标签移动或重排面板。
- 将所有文本都改为 hover-only；重要内容仍应可见或可通过明确操作打开。

这些能力需要更多布局状态管理与测试，课程原型先验证“画布聚焦 + 可调整辅助面板 + 单行控制条”是否改善调查效率。
