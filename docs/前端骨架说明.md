## 1. 这一版解决了什么

计划书把"重写 MC1 界面并为 MC2/自建集复用"列为主要工作量，但有两个前置问题必须先回答：

1. **11,577 个图元能不能画** —— 后端的毫秒级不代表浏览器画得动。
2. **双主题的色值从哪里来** —— 等界面写完再补 token 层，等于重写所有图表。

本版先用真实数据把这两件事钉死，再搭出工作区外壳，并把数据源从静态导出切换为 API。

## 3. 渲染结论

headless Chrome，1600×1000，DPR 1，纯 DOM/Canvas 操作，不含 React 开销：

| 图元数 | SVG | Canvas | 倍率 |
| ---: | ---: | ---: | ---: |
| 11,577（小时 × 类型明细） | 92–364 ms | 5.3–22.1 ms | 约 14–20x |
| 1,653（小时聚合） | 15–57 ms | 1.7–3.1 ms | 约 9–18x |

区间较宽是因为基准在**完整工作区页面内**运行：事件流已加载 50 行、侧栏可能打开，
`offsetHeight` 强制排版时会把周围 DOM 一起算进去。绝对值随页面内容浮动，
**稳定的是倍率**——无论如何，11,577 个图元的 SVG 都要数百毫秒，Canvas 始终在 20 ms 以内。
要拿到可比的绝对值，应把基准页单独挂载，这一点留待阶段 4 打磨时处理。

**决定：**

- **密集时间线走 Canvas。** SVG 单次就要约 100 ms，还会留下 11,577 个 DOM 节点，后续任何筛选、hover、主题切换都要再付一次布局成本。
- **SVG 留给稀疏且需要逐元素交互的视图**（聚焦关系图、选中子图、图例），那里节点数受上限控制。
- 两者都**在渲染时读取 CSS 变量**，主题切换触发重绘而不缓存色值。

## 4. 交互闭环

当前可从概览一路走到原始记录：

```text
概览（按天/按小时，类别可筛）
  → 拖动刷选时间窗 / 点击锚点跳到 ±1h
  → 事件流按筛选条件分页拉取
  → 点击某条事件
  → 证据侧栏：消息 / 参与者与关系边 / raw 原始记录
```

事件流中会标注 `含内心审议`（MC1 的 86 条）与 `已观测异常 / 已配置未观测`（自建集的 21/11 条），两者来源不同，不合并成一个"异常"标记。

锚点点击不是选中事件，而是把时间窗设到该时刻 ±1h 并移动游标——因为锚点是一个时刻，不一定对应单条事件。

## 4.1 MC1 双声道对照

MC1 的证据侧栏不走单声道引用块，而是并排放两块内容：

| 声道 | 内容来源 | 标注 |
| --- | --- | --- |
| 外发文本 | `details.content` | 原始观测 |
| 内部审议 | `raw.internal_state` 的 `reacting` / `rationalizing` / `deliberating` | 模型生成（分析线索） |

要点：

- **覆盖率必须显示**。全库只有 86 / 912 条事件有内部审议（9.4%），侧栏标题常驻"全库 86 / 912 条含内部审议（9.4%）"。不显示这个比例，演示时大多数点击会得到空右栏，看起来像功能坏了。
- **无审议文本有明确空状态**，并写明"这只表示源数据未收录，不能据此推断当时没有权衡"——避免把"没记录"读成"没发生"。
- 三种审议文本字段并存时用页签切换，单字段时直接展示，不做无意义的分栏。
- 侧栏在 MC1 下加宽到 476 px（窄屏 520 px），两栏各约 210 px 才读得下去。
- 事件流在 MC1 下多一个"仅含内心审议"开关（其余数据集不显示），把 912 条收窄到 86 条。筛选生效时行内不再重复打标。
- 块尾固定一段说明：审议文本属于分析线索，不是已证实的意图，结论需同时引用外发消息与上游事件。

实测（`npm run check:ui`）：勾选后 50 行全部带内心审议标记；打开首条，侧栏宽 476 px，左栏 `details.content`、右栏 `raw.internal_state`，覆盖率显示 86/912。

## 4.2 关系图

主画布顶部有「事件时间线 / 关系图」两个视图，共享同一份筛选与选中状态。

- **聚焦来源**：选中任意事件后自动聚焦它的 actor；在证据侧栏「关联」页点击任一参与者，
  会切换到关系图并把它设为新中心。点图上任意节点同样换中心。
- **布局**：`d3-force` 同步跑 350 tick 后静态渲染，不做动画——结果确定，
  减少动效设置下行为一致。力学结果的绝对尺寸与节点数不成比例，
  所以按包围盒统一缩放铺满画布，否则 20 个节点会挤在中间一小块。
- **标签策略**：节点 ≤ 30 时全标，标签朝背离中心的一侧排，避免压线；
  更多节点时只标中心与度数前 12 的节点，其余靠 `title` 悬浮提示。
- **边的编码**：实线 = 源记录中的关系（`source:*`），虚线 = adapter 派生（`adapter:*`）；
  线宽按同关系的事件数分档。图上明确写"边代表同一事件中的参与，不代表因果"。
- **裁剪**：服务端限 80 节点 / 300 边，超限时顶部显示"已裁剪，不能据此断言没有其它关联"。
- **一个必须知道的重复**：MC2 里 `person:emma_harbor` 与 `Agent/person:emma_harbor`
  是两个不同实体，图上会同时出现"emma harbor"两次。这是源数据的建模，不是渲染 bug，
  图例按类别分别计数（人员 / 智能体）。

实测：MC2 以 `victoria_rigging` 为中心得到 26 节点 / 35 边；点击 `ai systems` 后重新居中为 4 节点 / 3 边。

## 4.3 基线比较

第三个主画布视图。它把**当前刷选窗口**和**等长的前一个窗口**并排比较，
对应计划书里"逐步建基线并把实际行为与历史基线对比"的要求。

- **入口即窗口**：没有刷选时显示空状态并给一个"去时间线刷选"的按钮，不默认给一个假窗口。
- **必须按速率**：两个窗口长度可能不同（数据尾部被截断），所以统一折算成"每小时次数"。
  用绝对数比较时长窗口永远更"异常"。
- **偏离标记的措辞**：比值 ≥ 2 或 ≤ 0.5、或属"新增/消失"的行标红，但页面上写明
  「这是统计偏离，不是异常结论——需要回到事件流核对具体记录」。
- **基线为 0 不给无限倍**：接口返回 `ratio: null`，界面显示"—"并打「新增」标签。
- **漂移提示**：页脚常驻一句"基线只反映这段时间里通常发生什么，不反映应该发生什么"，
  提醒负载变化也会造成偏离。

实测（MC1，17:25 锚点窗口 16:25–18:25 / 101 条 vs 前一窗口 14:25–16:25 / 98 条）：
`public_post` 从 2.0/h 升到 7.0/h（3.5x），是唯一超过阈值的项；
MC2 同一视图按主体比较时有 5 项越界。

## 4.4 调查笔记

证据侧栏的第四个页签。它与事件选择解耦：没选事件也能记，只是不带事件引用。

- **写入服务端**（`build/notes.db`），刷新、重启浏览器都不会丢；这是"讲解到一半重启"的唯一兜底。
- **自动带上上下文**：保存时会存入当时的筛选摘要；若当前选中了事件，同时记录 `event_id` 与事件时间，
  列表里可据此回跳核对。
- **免责说明常驻**：笔记属于人工结论，与数据标签、规则线索并列但不同源，导出报告时应保留筛选快照。
- 状态条的「记录当前筛选」按钮走的也是这条链路，一键把当前筛选存成笔记。

实测：写入 → 列表出现 1 条、状态条角标变为 1 → 刷新页面后仍是 1 条 → 删除后归零，控制台无错误。

## 4.5 键盘操作

按计划书限定的范围实现，覆盖四类主要操作，不追求全界面可达：

| 分类 | 键 | 行为 |
| --- | --- | --- |
| 筛选 | `/` 或 `F` | 跳到关键词输入框并全选 |
| 时间刷选与回放 | `←` / `→` | 游标 ±1 小时；按住 `Shift` 为 ±6 小时 |
| 时间刷选与回放 | `空格` | 播放 / 暂停回放 |
| 时间刷选与回放 | `M` | 切换回放遮蔽 |
| 事件选择 | `↑` / `↓` | 事件流上一条 / 下一条，并滚动到可视区 |
| 证据侧栏 | `Enter` | 打开侧栏 |
| 证据侧栏 | `Esc` | 先关侧栏；侧栏未开时清空时间窗 |
| — | `?` | 打开 / 关闭快捷键说明 |

实现要点：

- 输入框、文本域、下拉框和 `contentEditable` 内一律不拦截按键，否则中文输入会被打断。
- 带 `Ctrl`/`Meta`/`Alt` 的组合键直接放行，交给浏览器。
- `↑`/`↓` 由事件流组件自己监听（它持有列表），因此只在时间线视图下生效；其余快捷键是全局的。
- `Esc` 有优先级：先关弹层、再关侧栏、最后清时间窗，避免一次按键做两件事。

实测（`check:ui`）：`?` 打开说明、`Esc` 关闭；`←` 游标从 17:05 退到 16:05；
空格使按钮变为「暂停」；`↓` 选中首行并打开侧栏；`Esc` 关侧栏；`/` 让焦点落在搜索框上。

## 4.6 对比度验收

不靠肉眼，直接解析 `tokens.css` 算 WCAG 2.1 比值：

```bash
python tools/check_contrast.py --strict
```

覆盖 24 组前景/背景配对：正文、次要文本、辅助文本（三种背景）、强调色、风险与待核验标记
及其底色、主按钮文字，以及 8 个类别色。正文阈值 4.5:1，图形与类别色 3:1。

**这一轮查出并修掉一个真问题**：浅色主题的 `--text-faint` 原值 `#7b8b86` 在白底上只有
**3.57:1**，而它被用在事件流时间、辅助说明等正文级文本上。深到 `#5c6e67` 后，
在面板 / 页面背景 / 沉底区域分别为 5.41 / 5.06 / 4.69，两套主题全部通过。

## 5. 主题 token 的使用约束

1. 组件、SVG、Canvas 内**不得出现色值字面量**；颜色只来自 `--bg`、`--panel`、`--text`、`--accent`、`--risk`、`--warn`、`--cat-1..8`。
2. 主强调色**不进入类别色表**；选中态用描边 + 底色共同表达，不靠颜色单独区分。
3. 类别色表两套主题各一份，色相不变、只调明度与饱和度。
4. 主题切换只改变量；筛选、选中、回放位置由 React 状态持有。
5. 减少动效有两层：系统 `prefers-reduced-motion` 与手动开关（`data-reduced-motion`）。

## 7. 过程中修掉的问题

| 问题 | 现象 | 根因与修复 |
| --- | --- | --- |
| 画布不铺满 | 容器 1320 px，画布固定 800 px | 首屏是加载态，`.chart-wrap` 未挂载，`useEffect` 里的 `ResizeObserver` 拿到 `null` 就返回。改 callback ref，卸载时断开 |
| 时间轴末刻度被裁 | 最右标签显示为 `2046-07-` | 末刻度以 `center` 对齐画在右边界上，改首左末右 |
| 遮蔽提示误报 | 游标停在末尾仍提示"遮蔽中" | 原判据是"最后一桶未结束"，改为"存在起始晚于游标的桶" |
| 切换数据集空结果 | 切到自建集 0 条 | 沿用上一个数据集的时间窗；改为切换时清空筛选、选中与游标 |
| 少桶图表铺满全宽 | 自建集只有 1 天，柱子撑满整幅 | 柱宽上限 48 px 并居中 |
| 事件流整列"无摘要" | 委派类事件无 `content` 字段 | 后端摘要增加委派/动作/通用键值回落，并跳过哈希等长值 |
