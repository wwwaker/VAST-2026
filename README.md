# 多智能体系统异常行为调查工作区

面向 VAST Challenge 2026 MC1、MC2 与自建工作流数据的可视分析工具，用于查看智能体活动、追踪消息和文件来源，并核对原始记录。

基本使用路径：**选择数据集 → 查看活动概览 → 筛选时段和对象 → 阅读相关记录 → 核对来源与证据**。

## 可以做什么

| 数据集 | 调查内容 | 主要功能 |
| --- | --- | --- |
| MC1 · 危机沟通 | 并购消息在解禁前如何出现于公开渠道 | 角色活动热力图、消息数量与情绪趋势、事件时间线、回复网络、消息上下文阅读 |
| MC2 · 内部系统活动 | 目标帖子引用了哪个文件，相关操作何时发生 | 发布来源链、文件轨迹、活动热力图、记录筛选与分页、独立阅读窗口 |
| CUSTOM · 工作流审计 | 审批绕过与旧版本传播在哪里留下记录 | 运行与阶段概览、角色流程、审计结果、正常运行配对比较、案例与结论保存 |

MC1 和 MC2 的页面顶部保留扩展工具入口，可访问更多比较与调查功能。

## 环境要求

- Python 3.11 或更高版本。
- Node.js 20 或更高版本。
- Python 自带的 SQLite 需支持 FTS5 和 JSON1。
- 推荐使用桌面浏览器和较宽的窗口，便于同时阅读图表与记录。

## 准备数据

数据文件与本地数据库不随代码仓库分发。启动前，需要已有 `build/mas.db`，或准备以下文件后导入：

```text
data/process/
├─ official_data/
│  ├─ MC1/
│  │  ├─ events.jsonl
│  │  └─ entities.json
│  └─ MC2/
│     ├─ events.jsonl
│     └─ entities.json
└─ custom_dataset/
   ├─ events.jsonl
   ├─ entities.json
   └─ labels.json
```

MC1 的情绪、关键词和背景信息还会使用配套的派生数据。迁移已有项目时，请一并保留 `data/` 目录。

## 安装与启动

以下命令从项目根目录开始执行。

安装后端依赖：

```shell
python -m pip install -r backend/requirements.txt
```

如果尚无数据库，准备好数据文件后执行一次导入；已有可用的 `build/mas.db` 时跳过：

```shell
cd backend
python -m app.ingest.cli --all --fresh
cd ..
```

安装并构建页面：

```shell
cd frontend
npm ci
npm run build
cd ..
```

启动本地服务：

```shell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在浏览器中打开 <http://127.0.0.1:8000>。保持服务窗口运行；停止服务可按 `Ctrl+C`。

如果页面无法读取数据，可打开 <http://127.0.0.1:8000/api/health> 查看数据库是否可用。需要重新导入时，先停止服务；导入完成并通过校验后才会替换原数据库。

## 使用方法

### MC1：从消息活动进入上下文

1. 在顶部选择 MC1，按角色、渠道、文本来源或关键词缩小范围。
2. 点击热力图格子，查看对应角色和时段的消息。
3. 点击消息打开上下文阅读窗口，核对回复和相关记录。
4. 使用回复网络查看角色之间的消息联系，或切换并排视图进行比较。

情绪趋势使用词典计分，仅辅助定位需要阅读的消息；背景事件和人工补充信息会单独标注来源。

### MC2：从发布锚点追踪文件

1. 在“发布锚点”中选择目标帖子或既往实例，查看日志明确引用的内容文件。
2. 点击来源文件，阅读创建、发布、删除等关联记录。
3. 在左侧设置时间、类别、事件类型、执行者或关键词，再点击“应用筛选”。
4. 点击活动热力图格子，筛选下方记录列表；再次点击或选择“清除格子选择”可取消。
5. 点击记录打开阅读窗口。逐层查看关联文件后，可返回上次阅读位置；按 `Esc` 关闭窗口。

文件搜索按文件名或路径查找。文件的全历史总数与当前筛选内的轨迹分别显示；同名前缀的文件只作为候选线索，不代表已证实的传播关系。

### CUSTOM：核对工作流运行

选择运行后查看各阶段与角色流程，再与正常运行进行配对比较。需要保留调查结果时，可使用案例、证据和结论功能，并导出 Markdown 或 JSON。

## 如何理解结果

- **时间**：MC1 源数据的时区未知，保留原始时间；MC2 使用 UTC，题目中的本地时间 04:21 对应 `2046-05-17 11:21:15 UTC`。时间筛选包含起点、不包含终点。
- **计数**：MC2 的记录数包含动作与回执，不等于发帖数量。
- **回复关系**：MC1 的直接回复、文本提及与指向未来的引用含义不同，不能互相替代。
- **文件正文**：MC2 的三条目标及既往异常发布记录未提供帖子正文或文件附件。来源链可以核对文件引用与操作，不能据此还原正文含义。
- **候选与证据**：同名、时间相邻或共同出现只能提供调查线索，不能单独证明因果或传播。
- **标签**：工作流的场景配置与实际观测结果分别呈现；配置为异常场景不代表每次运行都出现了异常。

## 本地保存与使用限制

- 调查笔记、案例和结论保存在本机 `build/notes.db`；需要迁移或备份时请保留该文件。分析数据库为 `build/mas.db`。
- 案例支持 Markdown 和 JSON 导出，截图需另行保存。
- 检索结果不按相关性评分排序。
- 图和轨迹可能设置展示上限，请留意截断提示，并使用记录分页继续核查。
- 本工具适合本地单用户调查，尚未验证多人并发、移动设备和投影显示场景。
