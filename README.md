# 多智能体系统异常行为调查工作区

面向 VAST Challenge 2026 MC1、MC2 与自建工作流数据的可视分析工具，用于查看智能体活动、追踪消息和文件来源，并核对原始记录。

基本使用路径：**选择数据集 → 查看活动概览 → 筛选时段和对象 → 阅读相关记录 → 核对来源与证据**。

## 可以做什么

| 数据集 | 调查内容 | 主要功能 |
| --- | --- | --- |
| MC1 · 危机沟通 | 并购消息在解禁前如何出现于公开渠道 | 角色活动与情绪热力图、股价与市场情绪、人工分析事件序列、回复网络、消息上下文阅读 |
| MC2 · 内部系统活动 | 目标帖子引用了哪个文件，相关操作何时发生 | 24 类型活动矩阵、明确角色关系、文件任务矩阵、局部时间泳道、来源实例比较与独立阅读 |
| CUSTOM · 工作流审计 | 审批绕过与旧版本传播在哪里留下记录 | 采集覆盖、四条件运行集合、版本证据、六角色调用轨迹、严格 normal 对照与原始记录阅读 |

MC1 和 MC2 的页面顶部保留扩展工具入口，可访问更多比较与调查功能。

## 环境要求

- Python 3.11 或更高版本。
- Node.js 20 或更高版本。
- Python 自带的 SQLite 需支持 FTS5 和 JSON1。
- 推荐使用桌面浏览器和较宽的窗口，便于同时阅读图表与记录。

## 准备数据

数据文件与本地数据库不随代码仓库分发。启动前，需要已有 `build/mas.db`，或准备以下文件后导入：

```text
data/process/
├─ official_data/
│  ├─ MC1/
│  │  ├─ events.jsonl
│  │  └─ entities.json
│  └─ MC2/
│     ├─ events.jsonl
│     └─ entities.json
└─ custom_dataset/
   ├─ events.jsonl
   ├─ entities.json
   └─ labels.json
```

MC1 的情绪、关键词和背景信息等还会使用配套的派生数据，包括 `data/process/views/manifest.json` 及其声明的文件（如 `mc1/views.json`）。仅复制数据库不能恢复全部功能；迁移已有项目时，请一并保留 `data/` 目录。派生文件缺失或与源事件版本不匹配时，对应能力会停用，重新导入数据库不会自动生成这些文件。

## 安装与启动

以下命令从项目根目录开始执行。

安装后端依赖：

```shell
python -m pip install -r backend/requirements.txt
```

如果尚无数据库，准备好数据文件后执行一次导入；已有可用的 `build/mas.db` 时跳过：

```shell
cd backend
python -m app.ingest.cli --all --fresh
cd ..
```

安装并构建页面：

```shell
cd frontend
npm ci
npm run build
cd ..
```

启动本地服务：

```shell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在浏览器中打开 <http://127.0.0.1:8000>。保持服务窗口运行；停止服务可按 `Ctrl+C`。

如果页面无法读取数据，可打开 <http://127.0.0.1:8000/api/health> 查看数据库状态、版本和已导入的数据集。需要重新导入时，先停止服务；导入完成并通过校验后才会替换原数据库。随后重启服务并刷新浏览器。

更新前端代码后，需重新运行 `npm run build`，再重启后端并刷新页面。开发时也可在 `frontend/` 运行 `npm run dev`，访问 <http://localhost:5173>；后端仍需单独运行在 8000 端口，页面会将 `/api` 请求转发给它。

## 使用方法

### MC1：从消息活动进入上下文

1. 在顶部选择 MC1，按角色、渠道、文本来源或关键词缩小范围。
2. 点击热力图格子，查看对应角色和时段的消息。
3. 点击消息打开上下文阅读窗口，核对回复和相关记录。
4. 使用回复网络查看角色之间的消息联系，或切换并排视图进行比较。

注意区分三类信息：

- **情绪热力图**：情绪值来自文本的词典计分派生结果，不是原始消息自带的字段，也没有执行 BERT 推理。格子取当前所选文本来源中有效分值的平均值，仅辅助定位需要阅读的消息。
- **股价与市场情绪**：股价、涨跌幅与市场情绪标签来自原始数据的 `market_snapshot`；图中将情绪标签映射为数值，部分变化指标由程序计算。它与消息文本的情绪计分口径不同。
- **事件序列 → 绕过禁运管控的那次发布（人工分析）**：事件与连接由人工整理并关联来源消息，不是原始数据自带或系统自动发现的完整事件链。

### MC2：从活动与明确关系进入局部过程

1. 使用与 MC1 一致的顶部时间轴设置全局时段，也可播放时间进度。左侧执行者和事件类型勾选后立即刷新，关键词与文件搜索在短暂输入停顿后刷新，无需“应用筛选”。两类筛选列表均支持独立滚动。
2. 活动概览显示 24 种事件类型。点击矩阵格子或类型名称只选择事件类型；点击上方活动记录数量柱状图的某一天，会另加单日筛选，并改变该柱颜色，**不移动顶部时间轴**。再次点击或“清除单日选择”可取消；更改全局时段会清除单日选择。
3. 对象分布、关系调查和证据记录跟随当前调查选择更新；活动概览保留全局筛选范围，便于继续比较。点“查看关系”进入更新后的关系区；也可收起概览，保留时间总量和当前选择。
4. 从文件分布进入文件任务或文件操作；任务关系支持有向图和发起者×目标矩阵。关系图支持拖动、鼠标滚轮缩放及缩放按钮。没有文件的事件也可直接查证。
5. 点关系，先看完整时间分布，再从具体记录进入“查看过程”。局部泳道区分主选和邻近上下文，包含日志明确的入向任务，可调整上下文时间窗口。左栏“异常发布与附近参与者 →”可直接建立前后 60 秒上下文，无需预先知道相关人物姓名。
6. 点泳道事件或证据记录打开独立阅读窗口，优先阅读消息正文、任务、问题或响应等有效内容，再展开结构化字段与原始来源。点击执行者文字可筛选主界面；关闭窗口后恢复原位置。
7. 新筛选会重新验证旧锚点，超出范围时停止画旧过程；明确固定的过程会标注不随当前选择变化。顶部可“返回上一步”“恢复全范围”，也可切换并排对比、显示筛选及各调查区域。
8. “有明确来源的发布实例比较”只比较明确引用来源文件的发布子集，不代表自动找出了全部相似异常。

任务排队只表示日志中的任务目标和参数，不代表执行成功；同名和时间相邻不升级为因果证据。旧版入口继续保留扩展工具。

### CUSTOM：核对工作流运行

1. 选择 CUSTOM 即进入新版，也可直接打开 <http://127.0.0.1:8000/?custom=reference>。采集概览按模型行×输入任务列排列，八组四色迷你柱图呈现四条件真实耗时，统一刻度并随数值加深颜色，缺采组合明确提示；点击行/列表头可分别筛选模型或任务。任务显示完整中文名称与原始文件名；运行对照矩阵按八组×四条件排列，可切换耗时、调用、版本和重复交接指标，使用统一批次尺度。点格子选中，再打开运行或比较；返回保留指标和格子选择。
2. 打开运行，默认查看版本、审核、读取、发布尝试、本地写入与结果的完整证据路径。controller 的流程选版单独展示；点击节点或边查看字段依据，再点记录阅读原始来源。
3. “运行轨迹”复用 MC1 同轨双端时间条，可拖动两端缩放、拖动选区平移；上方展示全程事件分布，并提供调用区间、操作顺序和交接顺序。角色与调用区间采用一致的图标及颜色，角色下拉支持复选、全选和清空。筛选只影响可见记录，不改变完整运行审计。聚合标记可以逐条阅读或放大展开。
4. “与同组 normal 比较”严格核对模型、输入任务和数据版本；八项指标按指标类别配色，用彩色当前条、灰色 normal 条与精确差值呈现。两侧证据图左右排列，窄栏将节点折成两层，轨迹共用秒数窗口；小窗口允许局部横向浏览，返回恢复原调查选择。
5. 左侧五条真实案例可直接查看旧版成功、审核绕过、正常修订、审核有效但拒绝和重复交接。事件/引用覆盖与正文/附件可用性分别显示；当前数据包缺少完整正文与调用附件，不能据此比较正文内容。

新版不使用旧 CUSTOM 样式。开发兼容入口为 `?custom=legacy`；旧版的笔记/导出能力没有加入新版初版主流程。实现和验证详情见 `docs/current/CUSTOM新版初版实施记录.md`。

## 如何理解结果

- **时间**：MC1 源数据的时区未知，保留原始时间，顶部时间筛选包含所选终点的最后一条消息；MC2 使用 UTC，时间窗口包含起点、不包含终点，题目中的本地时间 04:21 对应 `2046-05-17 11:21:15 UTC`。
- **计数**：MC2 的记录数包含动作与回执，不等于发帖数量。
- **回复关系**：MC1 的直接回复、文本提及与指向未来的引用含义不同，不能互相替代。
- **文件正文**：MC2 的三条目标及既往异常发布记录未提供帖子正文或文件附件。来源链可以核对文件引用与操作，不能据此还原正文含义。
- **候选与证据**：同名、时间相邻或共同出现只能提供调查线索，不能单独证明因果或传播。
- **标签**：工作流的场景配置与实际观测结果分别呈现；配置为异常场景不代表每次运行都出现了异常。

## 本地保存与使用限制

- 调查笔记、案例和结论保存在本机 `build/notes.db`；需要迁移或备份时请保留该文件。分析数据库为 `build/mas.db`。
- 案例支持 Markdown 和 JSON 导出，截图需另行保存。
- MC1 格子消息列表优先按关键词命中的文本来源权重排序，再按时间和消息编号排序；MC2 证据列表可按时间升序或降序分页。这些排序不表示证据可信度。
- MC2 对近期重复查询使用短期内存缓存并合并同时发起的相同请求；替换数据库或配套数据后，应重启服务并刷新页面，避免继续使用旧缓存。
- 图和轨迹可能设置展示上限，请留意截断提示，并使用记录分页继续核查。
- 本工具适合本地单用户调查，尚未验证多人并发、移动设备和投影显示场景。
